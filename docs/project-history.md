# 项目沿革：哪些时间能公开核对

时间线区分三个对象：早期探索、当前工作工程的版本记录、当前公开仓库。它们不能互相代替，也不应通过文件日期推断所有功能都在同一天完成。

## 2024：早期探索，有留存资料但未完整公开

现存 KPL 数据与分析工程材料包含 2024 年 5 月记录；旧工程线索和历史 README 还记录了决赛预测、多模型比较与 BO7 探索。

这些材料说明项目有早期前身，不等于当前网站当时已经存在，也不足以确定每个旧脚本最初编写的日期。完整旧源码尚未恢复。

**本次不公开原始早期文件、个人路径、编辑器记录或私人交流材料。** 如果以后需要展示早期资料，应由作者逐项确认、脱敏，并说明材料类型及其能证明的范围。当前公开 Git 不能为 2024 年的所有工作提供逐次提交证据。

## 2026 年 5 月：当前工程重构阶段

在早期探索基础上重新整理采集、字段、清洗与建模。留存接口验证脚本记录了 5 月 5 日的数据请求验证。

这属于本地工程沿革；本文不把它包装成当前公开仓库在 5 月已经对外发布的证明。

## 2026 年 7 月 21 日：V11 工作工程的版本记录

工作工程的 Git 保留该日 V11 平台的初始版本记录。提交信息虽然包含 “public release” 字样，但仅凭本地提交信息，不能证明当日的公开可访问状态。

因此时间线使用“V11 工程记录”，不再用它替代当前公开仓库的首次发布日。不在公开文档中链接私人仓库。

## 如何理解这些依据

提交日期主要证明版本历史中的一个节点，不单独证明所有内容当日对外可见，也不自动证明想法最早产生的日期。早期资料、提交记录、版本发布和网站部署应分别说明。

项目沿革用于解释自己的工作过程，不据此评价其他相似项目的来源。
