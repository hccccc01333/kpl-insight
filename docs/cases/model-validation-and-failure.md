# 模型验证与一次没有兑现的高概率判断

项目不只展示预测成功的比赛。验证需要同时检查数据隔离、概率质量、不同场景，以及判断失败时到底留下了什么证据。

## 什么才算模型验证

1. **先隔离比赛**：按时间、以整局划分训练、校准与测试。同一局的相邻分钟不能随机散到不同集合；辅助样本同样排除校准和测试局。
2. **再冻结流程**：特征、权重、校准与展示设置分别记录。不能反复参考测试集选模型，再称该测试集完全未见。
3. **报告概率质量**：Brier、校准误差、准确率、AUC 与分阶段指标结合解释，并报告局数、时点数、时间范围和模型指纹。
4. **保留反例**：检查翻盘、前期信息不足、版本变化、缺帧和延迟，不只选择最顺利的比赛。

Brier 是概率与 0/1 结果的平方误差，越低越好。单个预测 50% 的误差为 0.25，但真实模型评估应对测试样本汇总，并说明按帧还是按局加权。多个相关快照不能当成多场独立比赛。

### 当前公开范围能验证什么

- 源码中的训练、校准、划分与回测逻辑。
- 合成用例对数据身份、异常和契约的检查。
- 本文公开片段的字段算术、概率补数、展示取整与单点误差。

公开仓库没有附带完整真实测试集和权重，因此外部读者**不能仅靠本文复现总体性能**。演示和单元测试通过，也不等于预测准确率已经获得独立验证。

## 反例：TTG 约 94.8%，最终却是 JDG 获胜

比赛为 2026-06-26 北京 JDG 对广州 TTG 第 3 局。本局 camp1 是 TTG，官方最终胜方是 camp2 北京 JDG。

在第 767 秒的留存记录中：

- TTG 经济领先 4,297，击杀领先 4，推塔领先 4。
- 历史预测记录给予 TTG **0.94804**，给予 JDG **0.05196**。
- 该点的方向判断没有命中；以 TTG 最终获胜标签 0 计算，单点 Brier 为 **0.94804² = 0.8987798416**。
- 相同记录的采集延迟字段为 **60 秒**，时效性需要纳入检查。
- 这行记录没有模型版本和指纹，不能归为当前 V12 的独立测试结果。

高概率事件也会不发生，一次 94.8% 没兑现并不能单独证明“整个模型失效”或“校准一定有问题”。同样，也不能把反例从展示中抹去。需要在大量独立比赛中检查这类概率实际兑现的频率。

## 检查顺序：先排查口径，再研究模型

- **身份**：确认 camp1 / camp2 与战队名。此例的页面排序与大场顺序并不相同。
- **时点**：确认第 767 秒的状态还在进行，不使用终局摘要作为当时特征；另行检查采集延迟。
- **记录类型**：区分历史预测、当前重放和展示层数字。
- **数据**：核对经济、击杀、塔与资源是否存在缺失、重复或回退。
- **模型**：只有保存完整特征、权重版本和推理配置，才可能重建当时判断。
- **录像**：再核对阵容、站位、兵线与具体终结条件，不凭统计编造失误。

可能的研究方向包括时效性、模型对经济和资源的相对权重、后期特征及样本规模。**这些是待验证假设，不是本例已查明的失败根因。**

## 校准应该怎样展示

把预测概率分组，对照每组实际获胜比例，同时给出样本量、比赛数、时间范围与不确定性。测试段和直播段分别绘制，不能拼成一张曲线后统称“独立测试”。

在没有可公开复现的完整样本时，本页不绘制一张看似精确但无法核对的校准图。后续公开经过授权的测试集与模型指纹后，再提供可复算的完整图与结果。
